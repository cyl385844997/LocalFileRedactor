# LocalFileRedactor（本地文件脱敏工具）

一个**完全离线**的文件脱敏工具：把文档中的手机号、身份证号、银行卡号、邮箱、IP 等敏感信息，
**不可逆地**替换为占位符，输出到新文件。**绝不联网、绝不上传、绝不覆盖原文件。**

> ⚠️ 当前状态：**P0 + P1（优先级 1–6）已完成并通过测试（348 passed）**。
> **docx 已全通**：正文段落（跨 run、换行符、制表符）、超链接（含 `mailto:` 目标）、
> 表格（含合并单元格与嵌套表）、页眉页脚（含首页/ 偶数页）、批注、
> 文本框（含嵌套）、脚注、尾注。
> xlsx / pdf / pptx / OCR / GUI 尚未实现。详见下方「已知限制」与「路线图」。

---

## 这个工具解决什么问题

把一份含敏感信息的文件交给 AI 分析、或交给第三方处理之前，先把敏感信息抹掉。
抹得干净、且**不可逆**——不是画个黑框盖住，而是把底层字符真正删掉。

## 核心承诺

| 承诺 | 实现方式 |
|---|---|
| **绝不联网** | 依赖里无任何网络库；测试 `TestOfflineGuarantee` 扫描源码禁止 `requests`/`urllib`/`socket` 等导入 |
| **绝不覆盖原文件** | 源文件只读打开；输出路径与源路径相同则直接拒绝；输出已存在默认拒绝 |
| **不可逆脱敏** | PDF 走 PyMuPDF 真正的 `add_redact_annot + apply_redactions`（P3）；其余格式直接改写文本 |
| **报告零敏感内容** | 报告只记录规则名 + 命中次数 + 位置（页/段/行），**不记录任何原文**；不生成任何映射文件 |
| **规则加载失败即中止** | YAML 语法错 / 正则编译错 → 报错退出并指明**行号**，绝不静默跳过某条规则 |
| **部分未处理必须可见** | 因结构复杂而跳过的段落会在报告中单列"需人工复核"，不会藏在"成功"里 |

## 能力边界（重要，请先读）

**能做**（纯正则 + 校验位 + 字典）：

- 手机号、18 位身份证号（带校验位验证）、银行卡号（带 Luhn 校验）、邮箱、IPv4 / IPv6
- 校验位验证能显著降低误报：18 位设备编号不会被误判为身份证

**不能做**（本工具不覆盖）：

- ❌ **人名**（张三、李四）——纯正则做不到，需 NER 模型
- ❌ **地址**（XX 路 XX 号）
- ❌ **单位名**（XX 有限公司）
- ❌ **车牌号、社保号、mac 地址**（尚未内置规则，可自行在 YAML 里加）
- ❌ **间接识别**（如"张工"这种称谓）

如果你需要识别中文人名/地址/单位名，**本工具不能替代人工审查**。
这一点会写进 README 免责声明，也是开源时必须诚实说明的部分。

## 已知限制（Known Limitations）

### 通用

- **规则型识别**：只认 YAML 里配置的格式。人名、地址、单位名一律不识别。
- **不做语义判断**：一串 16–19 位数字若 Luhn 校验通过就会被当成银行卡号；
  校验位只能过滤格式错误，过不了"语义是否合理"这一关。
- **字体表 `fontTable.xml` 中的字体度量值可能被误匹配为银行卡号**
  （例如 panose1 值 `0502020204030204` 形式上是 16 位数字）。
  但本工具**不读写该文件**，它会随原样保留在输出文档中，因此**无实际影响**。
  （由独立验证时发现并记录。）

### docx（P1 全通：优先级 1–6）

**已处理**：正文段落、表格（含嵌套）、页眉页脚（含首页/偶数页）、批注、文本框（含嵌套）、脚注、尾注。
跨 run、`<w:br/>`、`<w:tab/>`、`<w:hyperlink>`、拼写校对标记、书签均支持。

**未处理 / 会跳过的**（本版**不脱敏**，需人工核查）：

| 位置 | 说明 |
|---|---|
| **域代码 / 修订标记 / 图形对象** | 含这些结构时**只跳过该段落**，同容器其他段落照常处理 |

**批注的处理方式**（优先级 5）：

批注存在独立 part `word/comments.xml`，正文侧通过 `commentRangeStart` /
`commentRangeEnd` / `commentReference` 三个元素的 `w:id` 与之关联。

- **只改批注段落里的文本，绝不碰任何 `w:id`**——正文侧的关联完全依赖它。
  实测处理后 Word 能正常打开，批注数与作者均保留。
- **批注作者名（`w:author` / `w:initials`）不脱敏**。本工具不识别"人名"，
  纯正则无法可靠判断，强行匹配会误伤。若作者名本身填了手机号或邮箱
  （有些人用邮箱当署名），**需人工处理**。
- **带批注标记的正文段落也正常脱敏**。这三个标记元素是**无文本、不占偏移**的
  （与 `<w:br/>` / `<w:tab/>` 不同，后者各占1 个字符并参与偏移映射），
  因此放行后不影响匹配。早期版本因未放行，导致真实文档里所有带批注的段落
  被当作"复杂结构"整段跳过——这是已修复的真实盲区。

报告位置标签为 `批注 #<w:id>`（用文档内部唯一 id，比遍历序号稳定）。

**文本框/ 脚注 / 尾注的处理方式**（优先级 6）：

三类容器的存储形态完全不同，遍历方式各异：

| 容器 | 存储位置 | 备注 |
|---|---|---|
| 文本框 | `document.xml` 内的 `<w:txbxContent>` | VML 与 DrawingML 共用此元素；嵌套用递归（上限 5 层） |
| 脚注/ 尾注 | `word/footnotes.xml` / `endnotes.xml` | part **没有 `element` 属性**，须解析 blob 后**显式写回**，否则不落盘 |

- 脚注/尾注里的 `w:type="separator"` / `"continuationSeparator"` 是
  **系统保留条目**（分隔线用），按 `w:type` 过滤，不参与处理。
- `w:id` 是正文侧 `footnoteReference` / `endnoteReference` 的关联依据，
  **绝不修改**（已验证处理后 Word 脚注/尾注数与引用位置均正常）。

**拼写校对标记与书签**：`w:proofErr`（拼写/语法校对）与
`w:bookmarkStart` / `w:bookmarkEnd` 都是**空元素、不占偏移**，已放行。
这一点很重要——**Word 默认会自动插入 `proofErr`**，
几乎所有人工编辑过的文档都有；不放行会让大量段落正文整段跳过、漏脱敏。

**表格的处理方式**（优先级 3）：

`document.paragraphs` **不包含表格内的段落**，所以表格必须独立遍历
（`document.tables` → `rows` → `cells` → `paragraphs`）。三个关键处理：

- **合并单元格按 XML 元素去重**。合并后 `cell(0,0) is cell(0,1)` 是同一个
  XML 元素，若重复访问会**虚增命中次数**。
- **嵌套表格递归处理**（深度上限 5 层，防病态文档）。
- **跳过粒度是段落而非整表**：域代码通常只在个别单元格（如页码栏），
  整表跳过会连带漏掉同表其他单元格的敏感信息。

报告位置标签用 `表1 R2C3` 格式（紧凑、与 Word 界面一致），嵌套表为
`表3 R1C1 内表1 R1C1`。

**页眉页脚的处理方式**（优先级 4）：

页眉页脚存放在独立 part（`word/header1.xml` 等），`document.paragraphs` 不含它们，
因此独立遍历。两个关键点：

- **只处理实际存在的页眉页脚**。实现从 `sectPr` 的引用元素直读，
  **不碰 `section.first_page_header` 等代理属性**——实测读取那些属性会
  自动创建原本不存在的 part（凭空生成空页眉并在 `sectPr` 里加引用），
  等于改变文档结构。
- **按 part 对象本身去重**（不用 `id()`，见表格部分的同源教训），
  避免"链接到前一节"时被重复处理、虚增命中次数。

页眉内的表格与超链接同样处理（页眉 part 有独立的 `rels`）。

报告位置标签形如 `页眉 第1节`、`首页页眉 第1节`、`偶数页页眉 第1节`。
报告会提示：首页/偶数页内容**仅在文档开启对应设置时才显示**，
但本工具仍会一并脱敏——"处理了却看不到变化"属正常现象。

**br/tab 的处理方式**：这类元素在文本流里各占 1 个占位字符（`\n` / `\t`），
使偏移量与真实字符位置保持一致；替换时元素本身原样保留，因此换行、制表符不会被破坏。

> 注意：号码**本身**被换行拆开时（`1380013⏎8000`）**不会**被识别。
> 这是有意为之——跨行的数字串不构成有效手机号，强行匹配反而会误伤。
> 真实文档中不存在这种写法。

**超链接的处理方式**（优先级 2）：

Word 把超链接拆两处存放：正文存显示文字 + `rId`，**真实 URL 存在
`word/_rels/document.xml.rels` 里**。因此正文正则扫不到 URL——
`mailto:someone@company.com` 会原封不动躺在 rels 文件里。处理方式：

| 对象 | 处理 |
|---|---|
| 显示文字 | 按现有规则脱敏，占位符替换文字 |
| `mailto:` 目标 | 改写 Target 为 `mailto:[邮箱]`（`[邮箱]` 做 URL 编码） |
| `https://` 等其他目标 | **原样保留**（不含敏感信息） |
| 内部锚点（`w:anchor`） | 只处理显示文字，**锚点不动** |

改写 Target 时**不删除 Relationship 条目**——删除会让正文里的 `rId`
变成悬空引用，属于"Word 能容忍但结构已损坏"的坏数据。

**已知限制**：URL 路径中的其他敏感信息（query 参数里的 token、路径里的工号等）
本版**不脱敏**，因为没有统一的识别规则，贸然匹配容易误判。

**格式保留的三个要点**：

1. **占位符继承首个 run 的格式**。手机号原本拆成"加粗 + 斜体 + 常规"三段，
   脱敏后 `[手机号]` 显示为**加粗**（跟随首个 run）。
2. **未被命中的 run 完全不被触碰**，格式自然保留。
3. **被删空的 run 会从 XML 中移除**。跨 run 替换会让中间/末尾的 run 文本变空，
   若保留空壳，它在 Word 里是**零宽度**的——不渲染也选不中，
   用户会看到"格式似乎存在却点不中"的困惑。移除后空白自然并入相邻 run。

## 安装

需要 Python 3.10+。

```bash
# 1. 建议用虚拟环境
python -m venv .venv
.venv\Scripts\activate

# 2. 安装 P0 所需依赖（只有 PyYAML 一个）
pip install -e ".[dev]"

# 后续阶段按需：
pip install -e ".[docx,xlsx,pdf]"    # P1-P3
pip install -e ".[gui]"              # P4
pip install -e ".[pptx,ocr]"         # P5
```

开发时也可以不安装，直接 `PYTHONPATH=src` 运行（pytest 已配置 `pythonpath`）。

## 快速开始

```bash
# 看看内置了哪些规则
redactor rules

# 先看会发生什么，不写任何文件（推荐第一步）
redactor dry-run 待脱敏文件.txt

# 确认无误后正式执行，输出到 redacted_output/
redactor run 待脱敏文件.txt

# 批量处理整个目录，保留子目录结构
redactor run 待脱敏目录/ -r -o 输出目录/

# 只用指定规则 + 编号占位符
redactor run a.txt --only 手机号 --numbered

# 出一份 JSON 报告
redactor run 待脱敏目录/ -r --report 报告.json --report-format json
```

### 常用参数

| 参数 | 说明 |
|---|---|
| `-o, --output` | 输出根目录，默认 `redacted_output/` |
| `-r, --recursive` | 递归子目录 |
| `--only 规则名 ...` | 只启用指定规则 |
| `--numbered` | 强制编号占位符（`[手机号#1]`）。**默认关闭**：编号会暴露"这两处是同一个号" |
| `--report` | 报告另存为文件 |
| `--overwrite-output` | 允许覆盖已存在的**输出**文件（仍永不覆盖原文件） |
| `REDACTOR_RULES_DIR` | 环境变量，整体替换规则目录 |

### 退出码

| 码 | 含义 |
|---|---|
| 0 | 全部成功 |
| 1 | 有文件未能处理（详见报告「需要人工处理的文件」） |
| 2 | 参数错误或规则文件错误 |
| 130 | 用户中断 |

## 扩展规则

编辑 `rules/builtin.yaml`，或新建 `rules/myrules.yaml`（同一目录下的多个文件会按文件名顺序合并）：

```yaml
rules:
  - name: 内部工号
    description: 公司内部工号格式 EMP-12345
    pattern: 'EMP-\d{5}'
    placeholder: '[工号]'
    validator: null      # 可选：id_card / luhn
    flags: [IGNORECASE]  # 可选：IGNORECASE/MULTILINE/DOTALL/VERBOSE/UNICODE
    numbered: false      # true 则输出 [内部工号#1]
    enabled: true        # false 则本条不参与匹配（但仍会被校验）
```

**加载是严格的**：字段拼错、重复规则名、非法正则、非法校验位名——任何一处出错都会
报错退出并指出行号。这是刻意设计：静默跳过一条规则，等于给用户制造"已脱敏"的错觉。

## 安全提示

- 本工具只能处理它"认识"的敏感信息。**脱敏后仍需人工抽查**，尤其是能力边界内的内容。
- 不要用本工具处理涉密文件后仅依赖自动结果对外提供。
- 生成的 `redacted_output/` 目录内的文件已脱敏，但**原始文件仍在原处**，请自行妥善保管。
