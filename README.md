# LocalFileRedactor（本地文件脱敏工具）

**离线脱敏工具 —— 拖入 docx / xlsx / pdf / txt，输出脱敏副本，原文件不改动。**

- 纯本地运行，**不联网、不上传**
- 界面是拖进来就完事，不需要配置任何代码
- 三大能力：**基础正则** / **范围泛化** / **人名识别**

```
拖入文件  →  勾选需要的能力  →  开始  →  拖入输出目录  →  完事
```

## 1. 快速开始

### 1.1 下载即用（Windows）

从 [Releases](https://github.com/<owner>/LocalFileRedactor/releases) 下载
`LocalFileRedactor.exe`，**双击运行** —— 不需要装 Python。

> **单文件 exe，约 60–90 MB**（内置 PySide6 / python-docx / openpyxl /
> PyMuPDF / jieba）。第一次运行会在 `%TEMP%` 解压，之后启动正常。

### 1.2 三步操作

1. **拖入文件** —— 把 docx / xlsx / pdf / txt 拖到窗口里
2. **勾选能力**（可选，见第 2 节）
3. **点「开始」** —— 选一个输出目录，等进度条走完

完成后双击结果文件即可打开。**原文件不会被修改或覆盖。**

### 1.3 源码运行

```bash
git clone <repo-url>
cd LocalFileRedactor

# 可选依赖（人名识别用，不装也能跑其它功能）
pip install --target=deps jieba

pip install -e .            # 核心依赖：PySide6 / python-docx / openpyxl / PyMuPDF / PyYAML

python -m redactor.gui.main          # 启动 GUI
python -m redactor.cli --help        # 命令行
```

## 2. 三大能力

### 2.1 基础正则 —— 内置格式规则

开箱即用，覆盖 6 类高频格式（**默认全部启用**）：

| 规则 | 覆盖内容 | 二次校验 |
|---|---|---|
| 手机号 | 1[3-9] 开头的 11 位 | — |
| 身份证号 | 18 位（末位可为 X） | GB 11643 加权校验位 |
| 银行卡号 | 16–19 位 | Luhn 校验 |
| 邮箱 | 常见邮箱地址 | — |
| IP地址 | IPv4（逐段 0-255） | — |
| IPv6地址 | IPv6 简写与完整写法 | 默认关闭（误报多） |

**关键设计**：格式类高风险规则都带**二次校验**。
例如 18 位号码若校验位不对，身份证规则会**静默拒绝**它 —— 这不是漏脱敏，
而是"这个号码本来就不是身份证"。实测扫 1799 个双校验通过的号码，零误吞。

**优先级契约**：身份证规则**必须**优先于银行卡规则（两者 pattern 长度都是 18，
只靠 YAML 顺序维持太脆弱）。这一点由
`RedactionEngine._apply_specificity_overrides()` 在代码里显式保证 ——
调整 YAML 顺序也不会退化。

### 2.2 范围泛化 —— 输一个关键字，脱敏整类实体

**问题**：静态词库要写死「某某有限公司」，换一家公司就得改配置。

**解法**：只写后缀（`公司`），凡是带该后缀的**整个实体**全部脱敏。

```yaml
# ~/.redactor/scopes.yaml
scopes:
  - name: 单位
    suffixes: ["有限公司", "公司", "集团", "大学", "项目"]
```

```
我们联系了XXXXXX有限公司  →  我们联系了[有限公司]
北京XXX科技公司                     →  [公司]
XXX大学                             →  [大学]
```

**三档严格度**（默认「平衡」）：

| 档位 | 覆盖后缀 | 实测误伤率 |
|---|---|---|
| 保守 | 仅法律/机构后缀（有限公司、集团、研究院…） | **0 / 22** |
| **平衡**（默认） | + 日常后缀（公司、大学、项目…） | 2 / 22 |
| 激进 | + 首字黑名单（这/那/每/某… 作首字时判误伤） | 1 / 22 |

**占位符按后缀**，不是按组 —— `XX大学` → `[大学]`，`XX公司` → `[公司]`。
这样跨文档比对时，同类实体的占位符保持一致。

GUI 里点击工具栏「⚙ 范围脱敏」打开独立对话框，含**强制预览**：
确定前就能看到哪些文本会被脱、哪些不会。

#### ★为什么不用正则

朴素写法 `[\u4e00-\u9fa5]{2,15}(公司|大学)` 实测**误伤 7/22**：
`他今天去公司了` 会被脱成 `他今天去[公司]`。

加负向前瞻 `(?<!去|到|在)` **完全无效**（误伤 7/22，一字未降）——
因为 `[一-龥]{2,15}` 是贪婪的，会**先把"去"吞进实体名**，
负向前瞻检查的位置变成"他"的前一个字，压根看不到"去"。

改用「排除字符」更糟：误伤涨到 **13/22** —— 排掉"在"之后，
正则引擎会跳过"在"继续往后吞，区间反而更长。

**最终方案：后缀锚点 + 反向逐字符扫描**（`scan_scope`）。
不用正则匹配实体名，只用正则定位后缀，然后从后缀往前逐字符扫，
遇到「停止字符」（数字/字母/标点/空白/功能字）即停。

这一步带来一个**关键的架构性质**：

> **数字是停止字符 → 命中区间绝不可能包含数字 → 范围脱敏永远不会吞掉手机号规则。**

朴素正则实测会把 `电话13888888888，公司` 整段吞掉（区间 16 字 > 手机号 11 字，
按"更长者优先"手机号被吃掉并以残缺形式泄露）。反向扫描版零吞数字。

### 2.3 人名识别 —— 基于 jieba 词性（可选，默认关闭）

用 jieba 的 `nr` / `nrfg` / `nrt` 三种人名词性识别中文人名。

```
张三1388888888      →  [人名][手机号]
项目负责人是李四      →  项目负责人是[人名]
欧阳修写过一篇文章    →  欧阳修写过一篇文章
```

**默认关闭**，原因：词性判定的误报率高于格式规则，
默认开启会让用户在没预期的情况下看到文档里多处 `[人名]`。

**大字金额剔除**：jieba 会把中文大写金额里的部分片段误判成人名
（实测 `已支付伍拾万元整` → `伍拾/nr`）。本工具默认剔除
含大写数字字符（零壹贰叁…拾佰仟万亿元角分圆）的片段。

实测：12 条负例语料，剔除前误伤 2 条，**剔除后误伤 0 条**。

> **jieba 是可选依赖**。没装时该功能静默关闭，程序照常运行。

## 3. 已知限制（请先读）

因为**脱敏工具的失败模式是"看起来成功了但没脱干净"**。
每条限制都附了实测数据，不含糊。

### 3.1 ★范围泛化：字号可能脱不完整

**实测**：

```
华为技术有限公司  →  [有限公司]        ← 只脱了后缀，"华为"保留
```

**为什么**：引导词「为」在"甲方**为**某某公司"里是动词，
在"华**为**"里是字号的一部分。反向扫描遇到「为」就停 ——
它无法区分这两种情况（**语言学歧义，不是工程问题**）。

试过"仅在未达最小长度时停止"，结果 `甲方为重庆某某公司`
会吞掉"甲方为"。

**取舍理由**：**字号不是敏感信息，少脱 2 字不构成泄露**；
反过来吞掉"甲方为"这类引导词，会把非敏感词写进占位符、**改变语义**，更危险。

**实测数据**（12 条正例 + 22 条负例）：

| 指标 | 平衡档 |
|---|---|
| 正例命中 | 12 / 12 |
| 完整覆盖 | 10 / 12（缺 2 处即上述字号截断） |
| 误伤 | 2 / 22 |
| **吞掉内置规则** | **0** |

### 3.2 ★范围泛化：2 处误伤不可消除

```
这家公司实力不错  →  [公司]
这个项目很难做    →  [项目]
```

「这/这个」是真指示代词，与字号首字**字形完全无法区分**。
激进档的首字黑名单能压到 1 处，代价是漏 1 个正例。

**建议**：先用保守档；跑完抽查报告里"单位"类命中，
确认无误再切到平衡档。

### 3.3 ★xlsx：元数据与结构

- **文档属性会残留**：Excel 的「作者 / 最后修改者 / 公司」等元数据
  **默认不改**。若文档曾被编辑过，原始作者名可能留在属性里。
  → 处理此类文件前请在 Excel 里检查 `文件 → 信息 → 属性`。
- **不使用 `read_only` 模式加载**：只读模式无法写回，
  因此加载大文件会比预期慢。
- **不支持 `.xls`**（旧版二进制格式），只支持 `.xlsx`。
- **数组公式、图表内嵌文本、透视表缓存**等结构化内容中的文本
  **不保证被处理**。遇到复杂表格请务必人工抽查。

### 3.4 ★PDF：扫描件暂不支持（★最易造成假成功）

**只处理带文字层的 PDF。** 扫描件（图片型 PDF）需要 OCR，
**本版本未实现**。

⚠️ **这是本工具最容易造成"假成功"的场景**：处理扫描件后会得到一份
"什么都没脱"的输出，而 GUI 会把该文件标为「成功」。

**判断方法**：用 PDF 阅读器打开，能选中/复制文字的才支持。
全是图片的扫描件请**先做 OCR 再脱敏**。

### 3.5 编号占位符会暴露同一性

```
默认（统一占位符）：张三 → [人名]     张三 → [人名]      两处相同
开启编号后：        张三 → [人名#1]   张三 → [人名#1]    ★出现次数
```

编号模式下，**同一个原文复用同一个编号**，等于告诉读者
"这两处是同一个人"。默认**关闭**，仅在明确需要时开启。

### 3.6 载体覆盖

| 载体 | 覆盖范围 |
|---|---|
| docx | 全通：正文（跨 run）、表格（含合并/嵌套）、页眉页脚、批注、文本框、超链接、脚注尾注 |
| xlsx | 单元格文本为主；结构限制见 [3.3](#33-xlsx元数据与结构) |
| pdf | 仅文字层；结构限制见 [3.4](#34-pdf扫描件暂不支持最易造成假成功) |
| txt | 纯文本全文 |
| pptx | **未实现** |
| 扫描件 / 图片 | **未实现**（需 OCR） |

### 3.7 其它

| 项 | 说明 |
|---|---|
| 超大文件 | 逐文件处理，不并发；大文件请耐心等进度条 |
| 密码保护 | 打不开的文件会显式报错，**不静默跳过** |
| 原文件 | **永不修改、永不覆盖**；输出必须指定新目录 |

### 3.8 设计原则

> **任何一条内容脱敏失败都必须显式告警，绝不静默跳过。**

跳过一个文件等于漏脱敏 —— 用户会以为已经脱干净了。
所以遇到打不开 / 不支持的文件，程序会明确告诉你，而不是假装成功。

## 4. 命令行用法

```bash
# 先看会发生什么，不写任何文件（推荐第一步）
python -m redactor.cli dry-run 合同.docx --report out.txt

# 正式执行
python -m redactor.cli run 合同.docx --out-dir redacted_output/

# 批量处理整个目录，保留子目录结构
python -m redactor.cli run ./合同目录 -r --out-dir redacted_output/

# 启用范围泛化
python -m redactor.cli run 合同.docx \
  --scopes scopes.yaml --scope-tier balanced --out-dir out/

# 启用人名识别
python -m redactor.cli run 合同.docx --names --out-dir out/

# 只用指定规则 + 编号占位符
python -m redactor.cli run 合同.docx --only 手机号 身份证号 --numbered
```

### 常用参数

| 参数 | 说明 |
|---|---|
| `--out-dir DIR` | 输出根目录（**必填**，工具永不覆盖原文件）|
| `-r, --recursive` | 递归处理子目录 |
| `--report FILE` | 输出脱敏报告（文本 / JSON）|
| `--only NAME...` | 只启用指定规则 |
| `--numbered` | 用编号占位符（⚠️ 暴露同一性）|
| `--lexicon PATH` | 自定义词库（`--no-lexicon` 禁用默认词库）|
| `--scopes PATH` | 范围泛化配置（`--no-scopes` 禁用）|
| `--scope-tier TIER` | conservative / balanced / aggressive |
| `--scope-strict-lead` | 范围泛化启用首字黑名单 |
| `--names` | 启用人名识别 |
| `--no-strip-da-zi` | 人名识别时不剔除大字金额 |

### 退出码

| 码 | 含义 |
|---|---|
| 0 | 全部成功 |
| 1 | 有文件处理失败 |
| 2 | 参数 / 配置错误 |

## 5. 自定义规则

规则与词库都放在 `~/.redactor/`：

```
~/.redactor/
  lexicon.yaml        # 自定义词库（精确列表）
  scopes.yaml         # 范围泛化（后缀泛化）
```

### 自定义规则（YAML）

```yaml
# ~/.redactor/rules.yaml
rules:
  - name: 内部工号
    description: 6 位工号
    pattern: '(?<!\d)[A-Z]{2}\d{6}(?!\d)'
    placeholder: '[工号]'
```

用 `--rules PATH` 指定。

### 自定义词库

```yaml
# ~/.redactor/lexicon.yaml
lexicon:
  - name: 甲方单位
    words:
      - 重庆某某有限公司
      - 北京某某科技公司
```

**词库 vs 范围泛化** —— 两者语义不同，别混：

| | 词库 | 范围泛化 |
|---|---|---|
| 写法 | 整条写出（`XX有限公司`）| 只写后缀（`公司`）|
| 命中 | 完全匹配 | 所有带该后缀的实体 |
| 适用 | 名单已知、少量 | 名单不定、大量 |

**优先级**：词库 > 范围泛化 > 内置正则
（同区间冲突时词库胜出 —— 词库是用户显式写死的，最精确）。

### ★打包陷阱（如果你也要打包第三方词典类依赖）

jieba 的 `dict.txt` 是**运行时按文件路径读取**的（不是 import 期加载的
Python 常量）。PyInstaller 只分析 `import` 语句，**不会**自动收
非 `.py` 数据文件 —— 打包后 jieba **不报错**，而是**静默退化成 HMM 模式**：
分词质量暴跌但程序照常跑。

必须显式声明：

```python
datas = collect_data("jieba")      # ← 命门
hiddenimports = ["jieba", "jieba.posseg"]
```

且**必须在打包产物内验证** `jieba.initialize()` 成功 ——
源码环境的测试完全推断不出这个问题。

### 项目结构

```
src/redactor/
  core/          规则 / 词库 / 范围配置加载、引擎、重叠消解
  recognizers/   正则 / AC 自动机 / 反向扫描 / jieba 人名
  handlers/      docx / xlsx / pdf / txt 各载体处理
  redactors/     占位符替换
  gui/           PySide6 界面
rules/           内置规则集
scripts/         测试、打包、验证脚本
```
